# Tei (Evan) Chang — Portfolio

Personal portfolio site built with **React**, **TypeScript**, **Vite**, and **Tailwind CSS**. The home page features an interactive physics-style experience; other sections cover profile, experience, projects, and contact.

**Live site:** [evch1204.github.io](https://evch1204.github.io/)

## Tech stack

| Layer | Choice |
|--------|--------|
| UI | React 19, TypeScript |
| Styling | Tailwind CSS v4 |
| Motion | Motion (`motion/react`) |
| Icons | Lucide React, react-icons |
| Build | Vite 6, ESLint |
| Hosting | GitHub Pages (GitHub Actions) |

## Project structure

```
├── .github/workflows/   # CI: build + deploy Pages
├── public/              # Static assets served as-is (resume.pdf, favicons)
├── scripts/             # Node scripts: contributions snapshot, favicon set
├── src/
│   ├── App.tsx          # Shell: tab state and history, header, page switch, footer
│   ├── main.tsx
│   ├── index.css        # Tailwind, theme tokens (fonts, page colour), focus-ring
│   ├── assets/images/   # profile.jpg, resume preview, and projects/<id>/ with
│   │                    # each project's card image, screenshots and figures
│   ├── components/      # Generic UI: Section, SectionHeading, Eyebrow, Tag,
│   │                    # Chip, PillLink, Modal, icons/ — knows nothing about
│   │                    # this site and imports nothing from content/ or pages/
│   ├── content/         # Facts and data, .ts and .json only (a content file
│   │                    # may name an icon component, never define one)
│   │   ├── site.ts      # Name, role, addresses, links, resume, school
│   │   ├── projects/    # types.ts, one file per project, index.ts (the
│   │   │                # ordered list, groups, featured project)
│   │   ├── experience.ts
│   │   ├── skills.ts
│   │   ├── tech.ts
│   │   └── contributions.json   # generated by `npm run contributions`
│   ├── hooks/           # Hooks with more than one consumer: useLocalClock, useLatest
│   ├── layout/          # Site chrome: Header, sliding-pill nav, phone TabBar,
│   │                    # SiteFooter, the tab list (nav.ts)
│   ├── lib/             # Leaf utilities: clock, download, format, links, motion, url
│   └── pages/           # One folder per tab; the page component at the root,
│       │                # its parts in components/, single-use hooks beside it
│       ├── home/        # HomeScreen, useHomeCtas, usePhysicsPlayground,
│       │   ├── components/   # PhysBlock, HomeFacts
│       │   ├── physics/      # The DOM playground: world, solver, collisions,
│       │   │                 # drag, blocks, loop, flights, playground (root)
│       │   └── styles/       # home-screen.css (entry) + blocks, playground, footer
│       ├── about/       # Profile, tech, GitHub activity, resume
│       ├── experience/  # Journey and education lists (OrgGroup, RoleRow)
│       ├── projects/    # Grid and the project page it opens into;
│       │                # useProjectRouting (history, scroll hand-off),
│       │                # useSlides, hero.ts, pictures.ts, addresses.ts
│       └── contact/     # Headline, actions, the address register
├── eslint.config.js
├── index.html
├── tsconfig.json        # References tsconfig.app.json (src) and tsconfig.node.json (vite.config)
├── vite.config.ts       # `@` is an alias for src/
└── package.json
```

Conventions: `@/` for any import that crosses a folder boundary, `./` for a
sibling, never `../` (the linter enforces it). Components default-export,
modules named-export. Layering is `lib → content → components → layout → pages → App`;
`physics/` imports nothing from React.

## Scripts

```bash
npm ci              # install dependencies (CI-friendly; Node 22, see .nvmrc)
npm run dev         # local dev server (port 3000)
npm run build       # typecheck + production build → dist/
npm run preview     # preview the production build locally
npm run typecheck   # TypeScript project build check (tsc -b)
npm run lint        # ESLint (typescript-eslint, react-hooks, import rule)
npm run deploy      # manual fallback: build + push dist/ with gh-pages
npm run contributions  # refresh src/content/contributions.json from GitHub
npm run favicon     # regenerate favicon.ico / .svg / apple-touch-icon.png
```

The GitHub Actions workflow is the canonical deploy; `npm run deploy` is only
the manual fallback for when Actions is unavailable.

There is no test suite. Layout changes are checked by building, then driving
headless Chrome over the DevTools protocol at phone and desktop sizes and
comparing screenshots against the previous build.

## Local development

1. Clone the repository.
2. `npm ci` (or `npm install`).
3. `npm run dev` and open the URL shown in the terminal (e.g. `http://localhost:3000`).

## Deployment (GitHub Pages)

The workflow **Deploy GitHub Pages** (`.github/workflows/pages.yml`) runs on pushes to **`main`**: it installs dependencies, runs `npm run build`, and publishes the **`dist`** folder.

In the repo: **Settings → Pages** — source should be **GitHub Actions** for this workflow to deploy.

`vite.config.ts` uses `base: '/'` for a **user** site (`username.github.io`). Project sites under a subpath need `base: '/repo-name/'` instead.

Tabs are React state, not URL routes, but every tab and every open project
page writes a history entry (`history.state`), so Back walks through tabs and
a reload returns to the same place.

## Customization

- **Copy:** page prose under `src/pages/`; project case studies in `src/content/projects/<id>.ts`, with a project's pictures in `src/assets/images/projects/<id>/`
- **Page title & meta:** `index.html`
- **Name, role, email, links, resume filename:** `src/content/site.ts`
- **Tabs:** `src/layout/nav.ts`; the pages themselves live in `src/pages/`
- **Home interaction:** `src/pages/home/` (`HomeScreen.tsx`, `styles/`, `physics/`)
- **Projects & featured content:** `src/content/projects/`
- **Experience & education:** `src/content/experience.ts`
- **Resume file:** add or replace `public/resume.pdf` (linked from the app)

## Environment & secrets

No API keys are required for the static site. Optional `.env` files are listed in `.gitignore`. Client-side code is public after deploy — do not put secrets in the repo or in `VITE_*` variables.
